# Tailscale Linux DNS Configurator Design (net/dns)

Source: tailscale/tailscale `net/dns/manager_linux.go` + `net/dns/direct.go`
(main branch, read 2026-08-03). Reference architecture for "VPN/TUN must
configure system DNS without shelling out and without assuming systemd".
Triggered by EasyTier PR #2424 review round 2: "不是所有 linux 都有 systemd".

## Mode detection chain (`dnsMode`)

Reads `/etc/resolv.conf` and classifies by header owner:

- `systemd-resolved` → use resolved via D-Bus — but first
  `resolvedIsActuallyResolver` (header alone is not proof, tailscale issue #2136):
  - `resolve` module present in `/etc/nsswitch.conf` `hosts:` line, OR
  - every nameserver in resolv.conf == 127.0.0.53 (allow repeated occurrences)
- `resolvconf` → style detection: debian → `debian-resolvconf`, openresolv →
  `openresolv` (both shell out to resolvconf — our no-shell constraint skips these)
- `NetworkManager` → NM D-Bus with version quirk table: only 1.26.0–1.26.5 are
  "safe" to program via NM (older ignore settings, newer ignore unmanaged-interface
  config, NM≥1.26.6 ignores DNS config for unmanaged interfaces entirely)
- unknown / missing → `direct` (last resort, always works)

## Direct mode (`direct.go`) — the file-based fallback

- **Backup**: before writing, `rename(resolv.conf, backupConf)` unless the file
  already carries our marker (never re-backup our own output).
- **Marker / ownership**: written file starts with `# generated by <tool>`; on
  restore, only overwrite if the CURRENT resolv.conf still carries our marker —
  otherwise someone else took over, drop our backup instead of clobbering.
- **Atomic write**: `rename` new file over resolv.conf; if rename fails
  (bind-mounted resolv.conf in containers → cross-filesystem move), fall back to
  copy + truncate (racy but better than broken DNS).
- **Restore** only when config is empty (IsZero) — otherwise the backup stays.
- **No split DNS**: `SupportsSplitDNS() == false` — resolv.conf only does
  `search`, no per-domain routing. Per-domain routing requires the resolved/NM path.
- **Kick resolved after direct write** (best-effort restart) so the system
  reconciles to the new file.
- **Permission errors swallowed on Synology** (non-root) — don't fail the whole
  config on EPERM.

## Lessons for EasyTier-style Rust implementations

- Probing only `Connection::system()` is NOT a resolver probe — the system D-Bus
  exists on many non-systemd distros, so the connection succeeds and
  `SetLinkDNS` fails with UnknownMethod/UnknownObject → DNS config silently no-ops.
  Probe the resolve1 SERVICE registration via the mandatory
  `org.freedesktop.DBus.Peer.Ping` on the resolve1 object path (every object
  implements Peer, so a reply proves the service is registered). ⚠️ Do NOT probe
  with `ListLinks` — verified 2026-08-03 on live systemd: it is NOT part of
  `org.freedesktop.resolve1.Manager` (UnknownMethod), the probe returns false on
  every system while compiling cleanly. Inspect the real interface with
  `busctl --system introspect org.freedesktop.resolve1 /org/freedesktop/resolve1`
  (methods include `.Ping`, `SetLinkDNS ia(iay)`, `SetLinkDomains ia(sb)`).
- Keep zbus optional + feature-gated (magic-dns) so non-D-Bus builds don't pull it.
- resolv.conf fallback = std::fs only, no new deps — consistent with the darwin
  file-based configurator already in the codebase.
- Backup path choice: `resolv.conf.easytier.bak` next to the original (same
  filesystem → rename works).
- Direct mode degrades match_domains to search domains (same as darwin).
